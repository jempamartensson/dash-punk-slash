# vfx-linux

A post-install setup that turns a fresh Arch Linux install into a VFX
workstation. It's tuned for AMD Strix Halo (Radeon 8060S, gfx1151) with ROCm,
a terminal-first, IRIX-inspired Hyprland desktop, rez-managed VFX libraries
and a local AI assistant.

## Status

| Step | What | State |
|---|---|---|

| 1b | Colour schemes (`vfx-theme`), isometric icon theme, VFX file types | written, tested in a sandbox |

## Install

Start from a minimal Arch install with a user that has sudo and working
network (archinstall, "minimal" profile, is fine). Before you begin, set the
BIOS UMA/VRAM size to its **minimum**, because the driver maps GPU memory
dynamically (see `VFX_GPU_MEM_GIB`).

```sh
git clone <this repo> ~/vfx-linux
cd ~/vfx-linux
./install.sh --dry-run   # see what it would do
./install.sh             # do it
sudo reboot
vfx-gpu-check            # after login
```

Run a single part with `./install.sh gpu` or `./install.sh desktop theme`. Every
module can be re-run safely.

## Modules

- **preflight** checks for Arch, a 6.15+ kernel, the AMD GPU and visible RAM, then updates the system.
- **base** installs CLI tools, the `paru` AUR helper and the weekly TRIM timer.
- **gpu** installs Mesa/RADV, ROCm HIP + OpenCL and adds you to the `render`/`video` groups. It raises the GPU's share of system RAM (TTM/GTT limit) to `VFX_GPU_MEM_GIB` and installs `vfx-gpu-check`.
- **desktop** installs Hyprland, waybar, foot, fuzzel, mako and greetd with a text login. It symlinks `dotfiles/` into `~/.config`, backing up anything already there.

- **theme** installs `vfx-theme`, applies a colour scheme, links the
  `dash-punk` icon theme into `~/.local/share/icons`, and registers file types
  for `.usd .usda .usdc .usdz .vdb`.

## Colour schemes

Four schemes live in `themes/*.toml`: **slate** (default), **teal**, **granite**
(dark) and **lavender**. Each one is a small set of named colours, modelled on
IRIX's scheme roles (basic background, text field, select fill, active window).

```sh
vfx-theme list          # * marks the current scheme
vfx-theme set granite   # apply one
vfx-theme next          # cycle (Super+Shift+T)
```

`vfx-theme` renders every file in `templates/` into `~/.config/vfx-theme/`,
then reloads Hyprland, waybar and mako. New terminals and launcher windows
pick up the change. The dotfiles read from that folder. Hyprland, waybar,
foot, fuzzel, mako, hyprlock and GTK are themed, and `qt.qss` is the Qt
stylesheet that usdview and other PySide tools will use in step 2.

To add a scheme, copy a `.toml`, change the colours and run `vfx-theme set <name>`.

## Icons

`icons/dash-punk` is an isometric icon theme generated by
`tools/make-icons.py`. Every icon uses the same 2:1 projection, with black
outlines, three-tone shading and a base with a drop shadow. It covers USD,
USDZ, OpenVDB, OpenEXR, rez packages, the terminal, the assistant and
folders. Edit the drawing code and re-run `tools/make-icons.py` to regenerate.
`tools/make-icons.py --preview sheet.html` also writes a contact sheet that
shows the selected (yellow) and drop-target (blue) states.

The design study behind all this is `design/look-book.html`.

- **rez** installs rez 3.5 into `/opt/rez`, the system libraries the VFX stack
  needs, and `vfx-rez-build`. It also creates the shared package repo
  `/opt/vfx/rez/packages`.

## VFX libraries (rez)

The libraries are built from source as rez packages, pinned to the
[VFX Reference Platform](https://vfxplatform.com) CY2026:

| Package | Version | | Package | Version |
|---|---|---|---|---|
| python | 3.13.18 | | ocio | 2.5.2 |
| PySide6 (Qt 6.8) | 6.8.3 (rez-pip) | | oiio | 3.1.19.0 |
| numpy | 2.3.x (rez-pip) | | ptex | 2.4.3 |
| tbb (oneTBB) | 2022.3.0 | | alembic | 1.8.12 |
| imath | 3.2.3 | | materialx | 1.39.5 |
| openexr | 3.4.18 | | opensubdiv | 3.7.0 |
| openvdb | 13.2.0 | | usd | 26.11.1 |

```sh
vfx-rez-build --list            # build order and what's installed
vfx-rez-build                   # build everything missing (about an hour)
rez env usd -- usdview shot.usda
```

Each recipe is `rez/packages/<name>/package.py` plus a `build.sh` that
downloads the pinned release and builds it with CMake/Ninja. Source
tarballs are cached in `~/.cache/vfx-src` and checked against
`rez/checksums.txt`. Your own packages go in `~/packages`, which rez
searches first.

**usdview** follows the colour scheme. The USD recipe patches usdview to read
`$VFX_USDVIEW_QSS`, and `vfx-theme` writes that stylesheet
(`~/.config/vfx-theme/usdview.qss`) for every scheme. usdview sets its prim
tree and attribute colours in code, so `rez/packages/usd/patch_usdview.py`
also makes it read `~/.config/vfx-theme/usdview-colors.ini`. Run
`vfx-theme set <scheme>` once after installing to write both files.

The usd package runs usdview through XWayland (`QT_QPA_PLATFORM=xcb`,
`PYOPENGL_PLATFORM=glx`), because PySide6 can't create a GL context on
native Wayland. In a VM it also sets `LIBGL_ALWAYS_SOFTWARE=1`, since Hydra
Storm needs OpenGL 4.5 and virtual GPUs only offer 4.3.

Copy `config.example.sh` to `config.sh` and edit it. Your copy isn't

## Keys

| Key | Action |
|---|---|
| Super+Enter | terminal |
| Super+D | launcher |
| Super+Q | close window |
| Super+F / V | fullscreen / float |
| Super+arrows | focus (Shift: move) |
| Super+1..9 | workspace (Shift: send window) |
| Super+L | lock |
| Super+Shift+T | next colour scheme |
| Print | screenshot region to clipboard |

The keyboard layout is set in `dotfiles/hypr/hyprland.lua` (`kb_layout = "us"`).

### Hyprland config is Lua

Hyprland 0.57 and later only read `~/.config/hypr/hyprland.lua`. The old
`hyprland.conf` format is no longer parsed, and if the Lua file is missing
Hyprland writes a stock one, which gives you an empty desktop. Our config is
`dotfiles/hypr/hyprland.lua`, with window rules in `rules.lua` and colours
loaded from `~/.config/vfx-theme/hyprland.lua`. Check it after editing:

```sh
Hyprland -c ~/.config/hypr/hyprland.lua --verify-config
```

In a VM, your host desktop may take the Super key. Click into the VM window
first, or use the viewer's Send Key menu.

## Known open questions

- Does Arch's packaged ROCm include gfx1151 kernels? `vfx-gpu-check` reports
  this. If it doesn't, step 2 will add a ROCm build that does.
- Hyprland's config API changes between releases. `--verify-config` (above)
  catches unknown options, rules and dispatchers.
